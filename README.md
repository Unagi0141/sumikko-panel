# すみっこパネル

https://github.com/Unagi0141/sumikko-panel

**現在 v0.9.0（ベータ）です。** 作者の環境でしか検証していません。

> 画面の端に居座る Web パネル。リポジトリ名は `sumikko-panel`。

X (Twitter) と mixi2 のタイムラインを、画面端の細いドックに**横並び**で常駐させる Windows 向けデスクトップアプリ。

- Windows の **AppBar** として画面の作業領域を予約するので、最大化した他のウインドウはドックの手前で止まります（上に覆いかぶさりません）。
- 全画面のアプリ（ゲーム・動画）が前面に出ている間は自動的に引っ込みます。
- 新しい投稿を検知すると通知音とバッジで知らせます。
- 対応サービスは JSON で定義され、コードを触らずに増やせます。
- 本文だけを拡大し、画像は畳んで、細いカラムでも読めるようにします。
- X が用意しているキー操作を使って、待機中の新着を再読み込みなしで流し込みます。

## 何をしているアプリか（先に読んでください）

**API は使っていません。各サービスの Web 版を、ログイン状態を保ったまま埋め込んで表示しています。**

- **X の API は実質使えない。** 無料枠は投稿系のみで、タイムラインの読み取りは有料プラン（Basic で月 $200 規模）が必要です。
- **mixi2 には公開 API がない。** 仕様が公開されていないため、Web 版を使う以外の選択肢がありません。

そのため、このアプリは実質的に **「タイムライン専用の、画面端に固定された細いブラウザ」** です。
各カラムは独立したセッションを持ち、一度ログインすれば次回以降も維持されます。

## 動かす

```bash
npm install
```

```bash
npm start
```

### デスクトップアイコンを作る

パッケージせずに、アイコンから起動できるようにします（`electron.exe` を直接指すのでコンソール窓は出ません）。

```bash
npm run shortcut
```

デスクトップに「すみっこパネル (開発版)」ができます。消すときは `npm run shortcut:remove`。
インストーラで入れた場合は、NSIS が通常のショートカットを作るのでこれは不要です。

アイコン画像（PNG と ICO）は依存パッケージなしで生成しています。作り直すなら `npm run icon`。

初回はトレイアイコンが増え、画面右端に幅 560px のドックが出て、X と mixi2 が横に並びます。
ログイン画面が出たら、**カラムの中で直接ログイン**してください。

> **ログインについての注意**
> 埋め込みブラウザからの「Google でログイン」「Apple でログイン」は、Google 側が
> 埋め込みブラウザを拒否するため失敗します。**メールアドレス／パスワードでのログイン**を使ってください。

## 画面の領域を予約する（AppBar）

既定でオンです。オンのあいだ、Windows の作業領域はドックのぶんだけ狭くなります。
タスクバーと同じ仕組みなので、他アプリを最大化してもドックに重なりません。

- 予約は **ドックを明示的に隠したとき（－ ボタン / トレイ / ショートカット）に解除**され、
  再表示で戻ります。画面に無駄な余白を残さないためです。
- 「マウスが離れたら自動的に隠す」や全画面アプリによる一時的な引っ込みでは**解除しません**。
  そのたびに他のウインドウがリサイズされて煩わしいためです。
- アプリ終了時には必ず解除します。強制終了された場合も、ヘルパープロセスが
  標準入力の切断を検知して解除します。

### 仕組み

`SHAppBarMessage`（Win32 API）を呼ぶ必要がありますが、Electron から直接呼ぶには
ネイティブモジュールのビルドが要ります。そこで [`src/main/win32-helper.ps1`](src/main/win32-helper.ps1) を
常駐の PowerShell 子プロセスとして起動し、標準入出力で行単位の JSON をやりとりしています。
追加の依存パッケージはありません。

> `.ps1` は **UTF-8 BOM 付き**で保存してください。Windows PowerShell 5.1 は BOM が無いと
> ファイルを ANSI として読むため、日本語コメントが壊れて構文エラーになります。

## 全画面アプリを妨げない

既定でオンです。1.2 秒ごとに前面ウインドウを調べ、次のいずれかなら全画面とみなしてドックを隠します。

- `SHQueryUserNotificationState` が `QUNS_RUNNING_D3D_FULL_SCREEN` / `QUNS_PRESENTATION_MODE` を返す
- 前面ウインドウの矩形がモニタ全体を覆っている（ボーダーレス全画面用）

`QUNS_BUSY` は全画面以外の「取り込み中」でも立つため、誤検知を避けて判定に使っていません。

## 新着の通知音

各カラムのページに [`column-preload.js`](src/preload/column-preload.js) を注入し、
`MutationObserver` でタイムラインを見張っています。

- **先頭付近に増えた投稿だけ**を新着とみなします。下へスクロールして過去の投稿が
  読み込まれたときに鳴らさないためです。
- 読み込み直後の 5 秒間は鳴りません（初回表示ぶんを新着としないため）。

### X での鳴り方（実測に基づく注意）

X の**ホームタイムラインは、放っておいても新着を先頭に差し込みません**。
代わりに「新しいポストを表示」のピルを出します。しかもこのピルの文言は固定で、
新着が 1 件でも 50 件でも変わりません。

そのため X のカラムでは、**ピルが「消えている状態から出た」瞬間**に 1 回だけ鳴ります。

- すでにピルが出ている状態でさらに新着が届いても鳴りません（X がその情報を出さないため）
- ピルをクリックして読み込むとピルが消え、次の新着でまた鳴ります
- 先頭にいるときに X が自動で差し込んだ場合は、投稿の検知側で拾って鳴ります

**より確実に鳴らしたいなら、カラムの URL をリストや検索のリアルタイムに変えるのが有効です**
（例: `https://x.com/i/lists/<ID>`、`https://x.com/search?q=...&f=live`）。
これらはピルを介さず先頭に差し込まれるため、投稿単位で検知できます。

mixi2 のカラムは投稿要素を直接検知しています（実測で 30 件の投稿要素を認識）。
- 音は WebAudio で生成した短い 2 音です（音声ファイルは同梱していません）。
  音量と「鳴らす間隔の下限」は設定から変えられます。
- カラムごとにオン / オフでき、ヘッダーには未読バッジが出ます。バッジかカラム名を
  クリックするとクリアされます。

検知はページの DOM 構造に依存するため、サービス側の作りが変わると効かなくなります。
その場合はカラム設定の「開発者ツール」でセレクタを調べ、`column-preload.js` の `SITES` を直してください。

## 新着の流し込み（ライブ更新）

旧 TweetDeck のように新着が流れ込み続ける挙動を、API 無しで再現します。

**X は新着を受信していても、先頭に自動で差し込まず「新しいポストを表示」のピルを出すだけ**です。
そこでこのピルが出ている間、代わりに押してやります。ただし押し方に条件がありました。

| 試した方法 | 結果 |
| --- | --- |
| JS の合成クリック（`el.click()`） | 効かない（ピルが消えず、先頭も変わらない） |
| `sendInputEvent` で本物のマウスクリック | 効かない |
| **`sendInputEvent` でピリオドキー** | **成功** |

これは裏技ではありません。ピルの `aria-label` に X 自身がこう書いています。

> 新しいポストがあります。新しいポストに移動するには、ピリオドキーを押してください。

再読み込みが起きないので、セッションも読みかけの位置も失いません。

動く条件は次のとおりです。ページ内のプリロードが判断し、キー送信はメインプロセスが行います
（ページ内から出す合成イベントでは効かないため）。

- 新着のピルが出ている
- **先頭にいる**（スクロール位置が 200px 未満）。読んでいる最中に差し込むと位置が飛ぶため
- 入力欄にフォーカスが無い（本文にピリオドが紛れ込まないため）
- 前回の送信から一定時間が経っている（既定 20 秒）

mixi2 にはピルに相当するものが見当たらないため、流し込みは行いません。

### 定期リロードはしません

ページは自前の接続で更新され続けるので、定期的な再読み込みは
**生きた接続と読みかけの位置を捨てるだけ**です。代わりに「一定時間まったく新着が無い」
ときだけ読み込み直す保険を入れてあります（既定 30 分、0 で無効）。

なお **API を使っていないので、いわゆるレート制限は存在しません**。
気にすべきは自動化された挙動と見なされないかどうかで、上の条件はそのための設計です。

## ログイン情報（既定では積んでいません）

**配布版にはログイン情報の保存機能が入っていません。** 暗号化していても、他人のパスワードを
預かる機能を無償で配れば、事故ったときの責任は作者に向きます。加えて X はログインの自動化に
エラーを返すことが実測で分かっており、規約上いちばん摩擦の大きい部分になります。

失うものはほとんどありません。**セッションは一度ログインすれば数か月維持されます。**

自分の環境でだけ使いたい場合は、環境変数で有効にします。

```bash
TLDOCK_CREDENTIALS=1 npm start
```

有効にすると設定パネルに「ログイン情報」が現れ、次のように動きます。

- パスワードは Electron の `safeStorage`（Windows では **DPAPI**）で暗号化して保管します。
  暗号文はこの PC のこの Windows ユーザーに紐づくので、ファイルをコピーしても他所では復号できません。
- **入力するだけで、ログインボタンは押しません。** 空の欄にだけ入れるので打ちかけの文字は消えません。
- 暗号化が使えない環境では、平文で保存せず**保存自体を断ります**。
- 保存時に**暗号化した直後へ復号し直して検証**します。「保存しました」と出たものは、
  少なくともその時点では復号できています。

無効なときは `credentials.js` を読み込まず、IPC の口も開きません。機能が存在しない状態になります。

> **送信まで自動で行う機能は取り止めました。** 実測の結果、mixi2 はメールの認証コードが必須で
> 完結せず、X はログインフローがエラーを返しました。詳細は開発の経緯として下に残してあります。

### 実測で分かったこと（自動ログインを取り止めた理由）

- **mixi2** はパスワードではなく **メールに届く 6 桁の認証コード**で入る方式でした。
  ユーザー名の入力までは自動で進みますが、コードの入力は人間にしかできません。
- **X** はログインフローが「問題が発生しました」というエラーを返しました。
  `/i/flow/login` を直接開く方法でも、トップページの導線を押す方法でも同じでした。
  自動化された試行が重なったことが原因の可能性があります。

## データの保存先を変える

> **名前を変えても保存先は動きません。** 表示名は「すみっこパネル」ですが、データの置き場は
> `%APPDATA%\Sumikko Panel` に固定してあります。表示名と保存先が連動していると、
> 名前を変えるたびに利用者の設定とログイン状態が迷子になるためです。
> 旧称（`Timeline Dock`）のデータが残っていれば、起動時に一度だけ自動で引き継ぎます。


設定パネルの「データの保存先」から、設定・ログイン情報・各サービスのログイン状態・注入 CSS を
置く場所（Electron でいう userData）を変えられます。C ドライブを空けたいときなどに。

- 「フォルダを選ぶ…」で選ぶと、**必要ならデータをコピーしてから再起動**します。
- 「既定の場所に戻す」で `%APPDATA%\Sumikko Panel` に戻せます。
- 元のフォルダは**消さずに残します**。問題なく動くのを確認してから手で削除してください。

### 仕組みと制約

userData は **app が ready になる前**に確定させる必要があるため、この処理だけは
`main.js` の一番上（他のモジュールを読み込むより前）で走ります。

保存先そのものは動かせますが、「どこに置いたか」を書いた小さなポインタ
`%APPDATA%\Sumikko Panel\data-location.json` だけは既定の場所に残ります。
ここが動くと次の起動で行き先が分からなくなるためです。

データのコピーは**次回起動の直後**（まだどのファイルも開いていない時点）に行います。
動作中はセッションの DB がロックされていて確実に運べないためです。
キャッシュ類（`Cache` / `GPUCache` / `Code Cache` など）と各種ロックファイルはコピーしません。
消えても作り直されるだけで、運ぶと壊れることがあるからです。

| ボタン | 動作 |
| --- | --- |
| （左のグリップ） | ドラッグでウインドウを移動。別のディスプレイに落とすと表示先として記憶します |
| ♪ | 新着音のオン / オフ |

### カラムのヘッダー

カラム名と未読バッジが常に出ています。操作ボタンはカーソルを乗せたときだけ現れます（狭いカラムを圧迫しないため）。

| ボタン | 動作 |
| --- | --- |
| ▾ / ▸ | 折りたたみ・展開（横並びのときは縦書きの細い帯になります） |
| （カラム名） | 先頭までスクロール＋未読クリア |
| ‹ | 戻る |
| ⌂ | 設定した URL（ホーム）へ戻る |
| ⟳ | 再読み込み。注入 CSS を編集したときもこれで反映されます |

### カラムに何を出すか

URL を変えるだけで、そのサービス内の好きなページを常駐させられます。

- `https://x.com/home` — ホームタイムライン
- `https://x.com/i/lists/<リストID>` — リスト（ノイズが少なく、細いカラムと相性が良い）
- `https://x.com/search?q=<検索語>&f=live` — 検索結果のリアルタイム
- `https://x.com/notifications` — 通知
- `https://mixi.social/` — mixi2

「その他のWeb」を選べば、任意のサイトも同じ枠で常駐できます。

## 文字サイズと画像の折りたたみ

細いカラムで一番効くのがこの 2 つです。カラム設定の「文字」と「画像を畳む」で変えられます。

### ブラウザの拡大とは違います

`zoom` を上げると文字も画像も余白もまとめて膨らみ、狭いカラムでは逆効果です。
そこで**本文の要素だけを名指しして `font-size` を上げる**方式にしてあります。

実測した結果、2 つのサービスは作りが正反対でした。

| | 文字の指定 | ルートの font-size を 2 倍にすると |
| --- | --- | --- |
| X | **px 直指定**（本文・名前・時刻すべて 15px、余白 16px） | 何も変わらない |
| mixi2 | **rem 基準**（html 10px / 本文 1.5rem） | 文字は 3.2 倍に。ただし余白も rem なら一緒に膨らむ |

どちらも「ルートをいじる」方式は不適切なので、**両方ともセレクタ狙い撃ち**に統一しています。
X は余白が px 固定なので、本文を拡大してもレイアウトは 1px も動きません。

### 仕組み

アプリは CSS 変数だけを注入し、ルール本体は編集可能な `.css` 側に置いています。

```css
/* アプリが注入: :root{--tld-text-scale:1.3; --tld-media-max:96px;} */
[data-testid="tweetText"] { font-size: calc(15px * var(--tld-text-scale, 1)) !important; }
[data-testid="tweetPhoto"] { max-height: var(--tld-media-max, none) !important; }
```

こうしておくと、**CSS を自分で書き換えても設定のつまみは効いたまま**です。

画像は既定で高さ 96px に詰め、クリックで開きます。画像そのものを縮めても
それを包む div が元の高さを保って空白が残るため、`:has()` で包んでいる側もまとめて詰めています。

## 対応サービスを増やす

対応サービスは [`src/services/services.json`](src/services/services.json) に定義されています。
**増やすのにコードを書き換える必要はありません。** JSON に 1 項目足すだけです。

初期状態で用意してあるのは X / mixi2 / Bluesky / Mastodon / その他のWeb の 5 つです。

```jsonc
{
  "id": "misskey",              // CSS のファイル名とセッションの保存先に使われる
  "label": "Misskey",           // 設定画面での表示名
  "home": "https://misskey.io/",
  "hosts": ["misskey.io"],      // ここに無いリンクは既定のブラウザで開く
  "textBase": 15,               // 本文の基準文字サイズ(px)
  "post": {                     // 新着検知に使う
    "selector": ".note",
    "key": { "selector": "a[href*=\"/notes/\"]", "attr": "href" }
  },
  "media": ".note img",         // 折りたたむ画像
  "live": null,                 // 新着の流し込み。対応していなければ null
  "loggedOut": {                // ログアウト判定
    "loggedIn": [".note"],      // これが見えていれば「ログイン済み」で打ち切り
    "paths": ["^/(signin|login)"],
    "present": ["input[type=\"password\"]"],
    "texts": ["ログイン"]
  }
}
```

`loggedOut` 以下を省略しても動きます。判定は「`loggedIn` に当たるものがあれば
ログイン済み → パス → 要素 → 文言」の順で見ます。

### CSS は無くてもよい

`styles/<id>.css` を置けばそのサービスだけに適用され、無ければ `generic.css` が使われます。
文字倍率と画像の折りたたみは generic.css にも入っているので、**CSS を書かなくても最低限は整います**。

### 文字サイズの仕組みはサービス共通

X と mixi2 で違うのは**セレクタと基準サイズだけ**で、仕組みは同一です。

```
アプリが注入:  :root{--tld-text-scale:1.3; --tld-media-max:96px; --tld-text-base:15px;}
サービス別CSS: <セレクタ> { font-size: calc(15px * var(--tld-text-scale)) !important; }
```

実測では X が px 直指定、mixi2 が rem 基準と正反対でしたが、**どちらもセレクタ狙い撃ちに
統一**したのでこの違いは吸収されています。新しいサービスでも同じ書き方が使えます。

## 見た目の調整（注入 CSS）

細いカラムは各サービスの標準レイアウトには狭すぎるので、サービスごとに CSS を注入して
余計な UI（X の左ナビ・右サイドバーなど）を隠しています。

CSS は `%APPDATA%\Sumikko Panel\styles\` に置かれ、そちらが優先して読み込まれます。
設定パネルの「CSS フォルダを開く」から編集し、カラムの ⟳ で反映してください。

**アプリを更新したときの扱い**（`.seeded.json` にこちらが置いた内容の指紋を記録しています）:

- 手を加えていなければ → 新しい既定に自動で入れ替えます
- 編集していれば → 触りません。更新があることだけログに出します
- 記録が無い（この仕組みより前から置かれていた）ファイル → `.bak` に控えを取ってから入れ替えます

> 「無ければコピー」だけにしていた時期があり、アプリ側の CSS を直しても
> 古いファイルが残り続けて**新しいルールが永久に届かない**という不具合になりました。
> 上の仕組みはその対策です。

`x.css` / `mixi2.css` / `web.css` の 3 つです。
**X の DOM は予告なく変わるため、この CSS はいつか効かなくなります。**
そのときはアプリ本体ではなく、この CSS を直してください。

## 構成

```
src/
  main/
    main.js            アプリ本体。ウインドウ、AppBar、全画面検知、トレイ、IPC
    columns.js         カラム 1 本ごとの WebContentsView。セッション分離、CSS 注入
    store.js           設定の既定値・正規化・保存
    credentials.js     safeStorage(DPAPI) によるログイン情報の保存
    data-location.js   userData の場所の切り替え（ready より前に走る）
    win32.js           PowerShell ヘルパーとの橋渡し（行単位 JSON）
    win32-helper.ps1   SHAppBarMessage / 全画面判定（UTF-8 BOM 必須、asar 展開必須）
  preload/
    preload.js         UI レイヤーへ公開する API
    column-preload.js  各カラムのページ内。新着検知・ログイン状態・自動入力
  renderer/
    index.html         ツールバー・カラム枠・設定パネル
    app.js             カラムの配置計算、設定 UI、通知音
    style.css
    strip.html         自動的に隠したときに画面端へ残す帯
  styles/              注入 CSS の既定値
tools/
  make-icon.js         アイコン PNG / ICO を生成（依存なし）
  make-shortcut.js     開発版のデスクトップショートカットを作る
```

### 表示の仕組み

タイムラインは `<webview>` ではなく **`WebContentsView`**（メインプロセス側のネイティブビュー）で
描画しています。これらは HTML の上に重なる別レイヤーなので、位置は自動では決まりません。

- レンダラー（`app.js`）が flexbox で枠を組み、各カラムの矩形を計算して IPC で送る
- メインプロセス（`columns.js`）がその矩形をビューに適用する

つまり **レイアウトの正は常にレンダラー側**です。横並び / 縦積みの切り替えも
`#columns` の `flex-direction` を変えるだけで、メイン側は矩形をそのまま受け取ります。

## 既知の制限

- **Windows 専用です。** AppBar と全画面判定は Win32 API に依存しています。
  他の OS では該当機能が無効になり、通常のウインドウとして動きます。
- **メモリは軽くありません。** Chromium のプロセスをカラムぶん抱えるので、2 カラムで数百 MB 使います。
- **高 DPI 環境は未検証です。** AppBar には物理ピクセルを渡すため、`scaleFactor` を掛けて
  変換していますが、モニタごとに倍率が違う環境では位置がずれる可能性があります。
- **新着検知と自動ログインはサービスの DOM 依存**です。作りが変わったら
  `column-preload.js` を直す必要があります。

## リリースする

electron-builder を設定済みです。

```bash
npm run dist
```

`dist/すみっこパネル Setup 0.1.0.exe`（約 110MB）ができます。動作確認済みです。

```bash
npm run pack
```

インストーラを作らず `dist/win-unpacked/` に展開するだけ。動作確認はこちらが速いです。

### インストーラの挙動

- **ユーザー単位のインストール**（管理者権限が不要、`perMachine: false`）
- インストール先を変更できる
- デスクトップとスタートメニューにショートカットを作る
- **アンインストールしてもデータは消しません**（`deleteAppDataOnUninstall: false`）。
  完全に消すなら `%APPDATA%\Sumikko Panel` を手で削除してください。

### パッケージするときの注意

**`src/main/win32-helper.ps1` は asar の外に出す必要があります。** PowerShell は asar の中の
ファイルを実行できないためです。`build.asarUnpack` に `**/*.ps1` を指定してあり、
`win32.js` 側もパスを `app.asar` → `app.asar.unpacked` に読み替えています。

バージョンを上げるときは `package.json` の `version` を変えてください。ファイル名に入ります。

### リリース前に把握しておくこと

- **コード署名をしていません。** 初回起動時に Windows SmartScreen の警告が出ます。
  消すには OV/EV のコード署名証明書（有償）が必要です。自分で使うだけなら「詳細情報」→
  「実行」で進めます。
- **自動更新の仕組みはありません。** 入れるなら `electron-updater` と配布先
  （GitHub Releases など）の設定が別途必要です。
- **サイズは約 110MB です。** Chromium を同梱するので、これ以上は大きく減りません。
- **他人に配る場合は、個人利用とは別の判断が要ります。**
  このアプリは X / mixi2 の Web 版を埋め込むクライアントで、公開 API を使っていません。
  一般配布は各サービスの利用規約と摩擦が生じる可能性があり、特に**自動ログイン機能**は
  自動化とみなされうる部分です。パスワードを預かる機能を他人に配ることの責任も伴います。
  身内で使う・自分だけで使うぶんには問題になりにくい、という程度に考えてください。

## デバッグ

```bash
TLDOCK_DEBUG=1 npm start
```

ウインドウのイベント、AppBar に認められた矩形、カラムから届いたログイン状態と
新着検知がコンソールに出ます。

UI レイヤーの `console.error` / `console.warn` は、通常起動でもメインプロセスのログに `[ui]` として流れます。
